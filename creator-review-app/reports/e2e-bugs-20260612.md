# Creator Review App Audit - 2026-06-12

Environment: local Next.js app with configured production Supabase and Google Drive services
Build reference: `bbb1650198e416e532b81e76c54669b601274593` plus workspace changes

## Fixed Defects

### S1: Admin mutations left lists stale

- Layer: frontend
- Frequency: Always
- Reproduction: Add a user, category, or assignment, or change a status.
- Actual: Success appeared, but the server-rendered list did not update.
- Fix: Added `router.refresh()` after successful admin mutations.
- Evidence: The reported user exists in Supabase as active admin; production build passes.

### S1: Unauthorized Google users were auto-provisioned

- Layer: cross-layer
- Frequency: Always
- Actual: Any successful Google login created an active creator record.
- Fix: Unknown accounts now go to `/access-denied`; admins must provision users.

### S1: Creator resubmission could not update the database

- Layer: API/backend
- Frequency: Always
- Actual: The creator client attempted an update prohibited by RLS.
- Fix: The API verifies ownership and active creator status, then performs the update with the server client.

### S1: Submission authorization relied on client filtering

- Layer: API/backend
- Frequency: Always for crafted requests
- Actual: A creator could submit metadata for an unassigned category; reviewer APIs did not enforce language assignments.
- Fix: Added server validation for role, status, category assignment, language, and category/file-type compatibility.

### S2: Failed mutations could leave orphaned files or partial users

- Layer: cross-layer
- Frequency: On downstream failure
- Fix: Failed submission/resubmission metadata writes remove new uploads. User creation rolls back if language assignment fails. Replaced resubmission removes the old stored file.

### S2: Drive failures were shown as successful syncs and could not be retried

- Layer: frontend/API
- Frequency: Always after Drive failure
- Fix: Drive failures now have distinct UI and appear in the review queue with a retry action.

### S2: API authentication returned HTML redirects

- Layer: API/middleware
- Frequency: Always without a session
- Actual: Client JSON parsing failed after redirect to `/login`.
- Fix: Protected APIs now return JSON `401`; protected pages still redirect.

### S2: Empty reviewer language scope exposed global counts

- Layer: backend/frontend
- Frequency: When an assigned language had no active category
- Fix: Empty scoped category sets now return zero records rather than removing the filter.
